# 틈 없는 read 확인 결과 (S26 Ultra, 2026-10-27)

Android 세션이 연구 세션에 보내는 보고다. 지시서 "틈 없는 read 확인 (S26 Ultra)"(2026-10-27)에 대한 답이다.

## 0. 결론
- **일반 모드에서는 틈을 없앨 수 없다.**
  - 어느 렌즈, 형식, 크기에서도 read 간격은 16.67 ms(60 fps)로 고정이다. SENSOR_FRAME_DURATION을 노출과 같게 요청해도 바뀌지 않는다.
  - 한 장을 읽는 시간(rolling shutter skew)이 6.3~15.9 ms라서 4.17 ms 간격은 물리적으로도 불가능하다.
- **고속 모드(120/240 fps)는 방법에 쓸 수 없다.**
  - 수동 노출을 무시한다. 4.17 ms를 요청하면 30 ms, ISO 99로 떨어지고 30 fps로 돈다.
  - 장마다 노출을 바꿀 수 없고, YUV ImageReader를 출력으로 받지 않는다.
- 지시서의 판정 규칙으로는 **"모두 안 됨 → 틈이 있을 때 어떻게 하나"**다(6절).

## 1. 방법
- probe: `GaplessDiag.kt` (topdown-base bc5c54f). 측정 run과 별개로 카메라를 직접 열고, 결과 metadata만 기록한다(YUV는 중앙 밝기도 기록). Duel2와 측정 run 코드는 바꾸지 않았다.
- 실행:

  ```
  adb shell am start -S -n com.sos.integrate/com.example.activeperception.MeasurementActivity --ez gapless_diag true
  ```

  출력은 logcat `SoSGaplessDiag`와 앱 파일 `gapless_diag.csv`다. 이 문서와 함께 [gapless_diag_2026-10-27.csv](gapless_diag_2026-10-27.csv)로 넣었다.
- 조건: 실내, 폰 고정, 자동 노출 끔, ISO 400. burst 하나는 8장이다.
- read마다 기록: SENSOR_TIMESTAMP, 결과의 SENSOR_EXPOSURE_TIME, SENSOR_FRAME_DURATION, SENSOR_SENSITIVITY, SENSOR_ROLLING_SHUTTER_SKEW, 톤맵·잡음 제거·윤곽 모드.
- **틈 = 연속 timestamp 간격 − 앞 read의 결과 노출.** timestamp는 노출 시작 시각이다.
- 후보마다 돌린 burst:
  - 노출 1/240 또는 1/120, SENSOR_FRAME_DURATION을 노출과 같게, 또는 비워서
  - 노출을 장마다 1/240 ↔ 1/120으로 번갈아(위 두 경우 모두)
  - YUV는 추가로 "선형" 요청(톤맵 직선 곡선 [0,0,1,1], 잡음 제거 끔, 윤곽 강조 끔)으로 같은 번갈아 burst
- 고속 모드는 자동 노출, 수동 노출(1/fps와 그 절반), 노출을 섞은 batch를 각각 0.7 s씩 반복했다. YUV ImageReader로 세션을 만들 수 있는지도 시도했다.

## 4. 관찰
1. **일반 모드 센서는 16.67 ms 주기로 고정이다.** 요청한 SENSOR_FRAME_DURATION(4.17, 8.33 ms)은 무시되고, 결과의 프레임 길이도 16.67 ms다. 해상도를 1280×720까지 낮춰도, 렌즈를 바꿔도 같다.
2. **노출이 끝나는 시각이 16.67 ms 간격에 맞춰진다.** 노출을 1/240과 1/120으로 번갈아 주면 timestamp 간격이 12.5 ms와 20.8 ms로 번갈아 나온다. 그래서 두 read 사이 틈은 정확히 16.67 ms − (뒤 read의 노출)이다.
   - 1/240이면 12.5 ms, 1/120이면 8.3 ms다.
   - 노출 변경은 매 read에 정확히 적용된다(지연 0).
3. **skew가 목표 간격보다 길다.** 주 카메라 RAW 15.9 ms, YUV 11.8 ms, 초광각 RAW 8.6 ms, YUV 6.3 ms다. 4.17 ms(1/240) 간격은 일반 모드 어느 출력으로도 불가능하다. 8.33 ms(1/120) 간격도 초광각 YUV(6.3 ms) 말고는 물리적으로 안 된다. 그나마 초광각 YUV도 실제 주기는 16.67 ms였다.
4. **고속 모드:**
   - 센서는 짧은 주기로 도는 것으로 보인다(주 카메라 결과 프레임 길이 4.16 / 8.38 ms, skew 3.6 ms).
   - 하지만 수동 노출 요청은 무시되고 30 ms 노출, ISO 99, 30 fps로 떨어진다.
   - 노출을 섞은 batch는 사실상 멈춘다(결과 0~1장).
   - 출력은 미리보기나 영상 인코더용만 되고, YUV ImageReader는 거부된다.
   - 초광각은 고속을 밝히지만 실제로는 60 fps로 돈다.

## 5. 한계
- **YUV 선형성 판정 보류.**
  - 선형 요청(톤맵 직선, 잡음 제거·윤곽 끔)은 결과 metadata에 그대로 반영됐다(TONEMAP_MODE = CONTRAST_CURVE, NR = OFF, EDGE = OFF).
  - 1/120 대 1/240 중앙 밝기 비율은 주 카메라에서 선형 요청 2.10~2.14, 기본 처리 1.82~1.84였다. 초광각은 1.26~1.35였다.
  - 하지만 장면이 너무 어두워 중앙 밝기가 255 중 1~5였다. 이 밝기에서는 기본 sRGB 곡선도 거의 직선이고 양자화가 커서, 비율로 판정할 수 없다.
  - YUV로 진행할 경우에만 밝은 장면(중앙 밝기 50~150)에서 다시 재면 된다. 다만 YUV도 16.67 ms 주기라 틈 문제는 같다.
- **고속 모드의 실제 간격.** 출력이 미리보기용 하나뿐이라, 묶음 4장 중 첫 장의 결과만 받았다. 장 사이 timestamp는 직접 보지 못했다. 영상 인코더 출력을 붙이면 볼 수 있지만, 수동 노출이 안 되므로 결론은 같다.
- **물리 렌즈 5, 6, 7번**은 논리 카메라 0번 안의 물리 스트림으로만 열 수 있어서 따로 찍지 않았다. 밝힌 일반 모드 최소 간격은 YUV 16.67 ms, RAW 33 ms다.

## 6. 판정과 논의할 점
지시서 규칙의 "모두 안 됨"에 해당한다. 다음 논의에 쓸 사실:
- 틈의 길이는 정확하고 일정하다. read 쌍의 틈은 16.67 ms − (뒤 read 노출)이고, 노출 끝 시각이 16.67 ms 간격으로 맞춰진다. 그래서 두 read 사이 시간 차는 미리 정확히 알 수 있다(1/240 쌍은 노출 시작 기준 16.67 ms).
- 노출은 read마다 지연 없이 바뀐다. 진짜 긴 노출 한 장(예: 1/120)을 다음 read로 바로 찍을 수 있다. 비용은 16.67 ms 한 칸이다.
- 지금 Duel2의 합성 이웃(1/240 두 장 합 = "1/120")은 두 장 사이 16.67 ms 동안의 움직임을 그대로 겹친다. dark에서 합으로 만든 기준 사진이 약한 원인(DUEL2_RESULTS 3.2절)과 같은 현상이다.
